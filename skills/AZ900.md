# AZ-900 Microsoft Azure Fundamentals

AZ-900 대비 시험지를 생성하기 위한 자격증 SKILL이다. 유형 어휘, 문항 서식, 채점 규칙은 `문제 유형.md`를, 생성·검증 절차는 `생성 규칙.md`를 따른다. 이 문서는 출제 범위, 질문 카테고리, 문제 본문 구조, 표기 규칙, 최신성 기준만 추가한다.

## 1. 역할

- AZ-900 합격을 돕는 튜터로서 출제한다. 모든 문항은 아래 출제 범위에서 합격 역량에 기여해야 한다.
- 기출 덤프 문항을 적극 활용하여 문제를 생성한다. 덤프에서는 문항 형식과 시나리오 패턴 및 문항 내용을 사용하고, 내용은 공식 학습 가이드를 근거로 새로 작성한다. 덤프의 정답 표시는 근거로 쓰지 않는다.

## 2. 시험 형식

- 시행: Microsoft. 방식: 컴퓨터 기반 시험. 시간: 45분. 합격: 1000점 만점에 700점 이상. 문항 수는 40~60개 안팎이며 공개되지 않는다.
- 실제 문항 형식은 단일 선택, Yes/No 진술 판단, 드래그앤드롭 배치이다.

## 3. 시험지 구성

기본 구성은 10문항이다.

| 시험 형식 | 문항 유형 | 기본 문항 수 |
|---|---|---|
| 단일 선택 | 사지선다형 | 6 |
| Yes/No 진술 판단 | TrueFalse | 2 |
| 드래그앤드롭 배치 | 빈칸 채우기형(보기형) | 2 |

- 영역별 문항 수는 클라우드 개념 3, 아키텍처·서비스 4, 관리·거버넌스 3이다.
- 서술형·논술형·실습 유형은 사용자가 명시적으로 요청한 경우에만 출제한다.
- 빈칸 채우기형은 보기에 있는 항목을 빈칸에 배치하는 방식으로 출제한다.
  - 빈칸은 3~4개로 하고, 보기는 빈칸 수보다 2개 이상 많게 둔다.
  - 오답 보기는 같은 범주에서 혼동하기 쉬운 서비스나 옵션으로 채운다. 범주가 다른 항목은 쓰지 않는다.
  - 각 빈칸의 설명에는 비슷한 항목과 구분되는 근거가 있어야 한다. 보기만 보고 소거법으로 풀리지 않게 한다.
  - 질문에서 보기를 번호나 위치로 지칭하지 않는다. 보기 순서는 시스템이 섞는다.

## 4. 출제 범위

1. **클라우드 개념**: 클라우드 컴퓨팅 정의, 공동 책임 모델, 퍼블릭·프라이빗·하이브리드, 소비 기반 모델, 가격 모델 비교, 서버리스, 고가용성·확장성·안정성·보안·관리 용이성, IaaS·PaaS·SaaS와 사용 사례.
2. **Azure 아키텍처와 서비스**: 리전·리전 쌍·주권 리전, 가용성 영역, 데이터센터, 리소스·리소스 그룹·구독·관리 그룹과 계층, 컴퓨팅 유형 비교(컨테이너, 가상 머신, 함수), 가상 머신 옵션, 애플리케이션 호스팅, 가상 네트워크·서브넷·피어링·DNS·VPN Gateway·ExpressRoute, 퍼블릭·프라이빗 엔드포인트, 스토리지 서비스·계층·중복성·계정 옵션, 파일 이동·마이그레이션 도구, Microsoft Entra ID·Domain Services, 인증 방법, 외부 ID, Conditional Access, RBAC, Zero Trust, 심층 방어, Microsoft Defender for Cloud 및 기타 등.
3. **Azure 관리와 거버넌스**: 비용 요인, 가격 계산기, 비용 관리, 태그, Microsoft Purview, Azure Policy, 리소스 잠금, Azure 포털, Cloud Shell·CLI·PowerShell, Azure Arc, IaC, ARM과 ARM 템플릿, Azure Advisor, Service Health, Azure Monitor와 Log Analytics·경고·Application Insights 및 기타 등.

위에 기재되진 않았으나 범위 내(Azure) 주제 또한 생성 가능. 문항 수가 3개 이상이면 3개 영역을 각각 한 번 이상 포함한다.

## 5. 질문 카테고리와 문항 유형 매핑

문항 하나는 아래 카테고리 중 하나를 사용한다.

| 카테고리 | 레퍼런스 | 문항 유형 |
|---|---|---|
| a) 서비스·개념 식별 | 설명에 해당하는 서비스·개념 고르기 | 사지선다형 |
| b) 시나리오별 서비스 선택 | 요구사항에 맞는 서비스·옵션 고르기 | 사지선다형 |
| c) 요구사항 충족 판단 | 제안한 해결책이 목표를 충족하는가 | TrueFalse |
| d) 진술 참거짓 | 서비스 특성에 대한 진술의 참거짓 | TrueFalse |
| e) 배치·분류 | 항목을 알맞은 범주·단계·역할에 배치 | 빈칸 채우기형 |
| f) 비용·SLA·거버넌스 판단 | 비용 요인, 가용성, 정책 적용 효과 | 사지선다형, 빈칸 채우기형 |

## 6. 문제 본문 구조

`question` 필드는 아래 순서를 따른다. 해당하지 않는 항목은 생략한다.

1. **시나리오**: 회사나 팀의 상황을 3~6문장으로 제시한다. 개념 식별 문항에서는 생략할 수 있다.
2. **요구사항**: 충족할 조건을 불릿으로 나열한다. 서로 충돌하지 않아야 한다.
3. **질문**: 하나의 질문만 한다. 선택 개수가 있으면 명시한다.

TrueFalse 문항은 한 개의 진술로 구성한다. 시나리오와 목표를 제시하고 "제안한 해결책이 목표를 충족한다"는 진술의 참거짓을 묻는다. 여러 문항이 같은 시나리오를 공유하는 묶음은 쓰지 않는다. 각 문항이 독립적으로 풀려야 한다.

## 7. 출제 규칙

1. 사지선다형의 오답 보기는 실제 Azure 서비스나 옵션 중에서 고르되 요구사항을 충족하지 못해야 한다. 존재하지 않는 서비스명을 만들지 않는다.
2. 가격, 할인율, SLA 수치, 리전 수, 한도값처럼 수시로 바뀌는 수치는 출제하지 않는다. 구조·개념·선택 기준만 묻는다.
3. 서비스명이 바뀐 항목은 현재 명칭만 쓴다. 예: Azure Active Directory가 아니라 Microsoft Entra ID.
4. 시행 예정이거나 Preview인 기능은 출제하지 않는다. 범위에 명시된 항목의 일반 제공 기능만 다룬다.
5. 질문에 기준 시점을 명시하지 않아도 되지만, 시점에 따라 달라질 수 있는 사실은 출제하지 않는다.

## 8. 표기 규칙

1. 서비스명, 기능명, 약어는 영어 원형을 쓴다. 예: `Azure Policy`, `RBAC`, `ExpressRoute`.
2. 문항은 한국어로 작성하고, 명령어·템플릿 코드는 원형을 유지한다.
3. 한 문항 안에서 같은 개념은 같은 표기로 통일한다.

## 9. 난이도 기준

`문제 유형.md`의 상/중/하 정의를 따르며, 이 자격증에서의 기준은 다음과 같다.

- **하**: 정의·용어 식별, 단순 진술 판단(카테고리 a, d).
- **중**: 요구사항에 맞는 서비스·옵션 선택, 단순 배치(카테고리 b, c, e).
- **상**: 둘 이상의 조건을 동시에 만족하는 선택, 비용·거버넌스 영향 판단(카테고리 f).
