# 정보보안기사 실기

정보보안기사 실기(정보보안 실무) 대비 시험지를 생성하기 위한 자격증 SKILL이다. 유형 어휘, 문항 서식, 채점 규칙은 `문제 유형.md`를, 생성·검증 절차는 `생성 규칙.md`를 따른다. 이 문서는 출제 범위, 질문 카테고리, 문제 본문 구조, 표기 규칙, 법규 기준만 추가한다.

## 1. 역할

- 정보보안기사 실기 합격을 돕는 튜터로서 출제한다. 모든 문항은 아래 출제 범위에서 실기 합격 역량에 기여해야 하며 일반 상식·잡학 문항은 내지 않는다.
- 정보 기준일: 2026-10-07.

## 2. 시험 형식

- 시행: 한국방송통신전파진흥원. 방식: 정보보안 실무 필답형(전부 주관식). 시간: 180분. 합격: 100점 만점에 60점 이상.
- 2023년 이후 구성: 단답형 12문항(문항당 3점, 36점), 서술형 4문항(문항당 12점, 48점), 실무형 2문항 중 1문항 선택(16점). 총 17문항, 100점.
- 객관식이 없으므로 TrueFalse와 사지선다형은 사용하지 않는다. 사용자가 명시적으로 요청한 경우에만 출제한다.
- 세부 구성은 회차에 따라 달라질 수 있다. 사용자가 유형별 문항 수와 배점을 지정하면 그에 따른다.

## 3. 시험지 구성

기본 구성(시험 모사)은 단답형 계열 12문항(3점), 서술형 4문항(12점), 실무형 1문항(16점)이다. 앱이 택1 선택을 지원하지 않으므로 실무형은 1문항만 출제한다.

| 실기 문항 구분 | 사용 가능한 문항 유형 |
|---|---|
| 단답형 | 단답형, 빈칸 채우기형(무보기형), 단답형 실습 |
| 서술형 | 서술형, 논술형(요청 시) |
| 실무형 | 서술형 실습, 단답형 실습 |

## 4. 출제 범위

1. **시스템 보안**
2. **네트워크 보안**
3. **애플리케이션 보안**
4. **정보보안 일반**
5. **정보보안 관리 및 법규**

범위 밖 주제는 임의로 출제하지 않는다. 문항 수가 5개 이상이면 5개 영역을 각각 한 번 이상 포함한다.

## 5. 질문 카테고리와 문항 유형 매핑

문항 하나는 아래 카테고리 중 하나를 사용한다.

| 카테고리 | 레퍼런스 | 문항 유형 |
|---|---|---|
| a) 용어·개념 | 설명을 보고 해당 용어를 쓰시오 | 단답형 |
| b) 원리·비교 설명 | 두 방식의 동작 원리와 차이를 설명하시오 | 서술형 |
| c) 로그·패킷 분석 | 웹·인증 로그, tcpdump 출력에서 공격 유형을 식별하시오 | 단답형 실습, 서술형 실습 |
| d) 설정·룰 해석·작성 | iptables 규칙의 동작을 쓰시오, 조건에 맞는 룰을 작성하시오 | 단답형 실습, 서술형 실습 |
| e) 취약점 분석 | 코드·요청 예시에서 취약점명, 원인, 대응을 쓰시오 | 서술형 실습 |
| f) 명령어·도구 | 목적에 맞는 명령어와 옵션, 결과 해석 | 단답형 실습 |
| g) 암호·프로토콜 절차 | 절차의 빈칸 채우기, 알고리즘 특성 | 빈칸 채우기형, 단답형 |
| h) 법규·관리 | 제도의 요건·절차·통제 항목 | 빈칸 채우기형, 단답형, 서술형 |
| i) 시나리오·정책 | 침해사고 대응 절차, 보안 정책 수립 | 서술형, 논술형 |

## 6. 문제 본문 구조

`question` 필드는 아래 순서를 따른다. 해당하지 않는 항목은 생략한다.

1. **상황 설명**: 1~5문장으로 시나리오를 제시한다. 용어·개념 단답형에는 생략할 수 있다.
2. **자료**: 로그, 설정, 코드, 패킷, 명령어 출력을 언어 태그를 붙인 코드블록으로 제시한다. 로그·패킷·설정 분석(c, d, e, f)에서는 필수이다.
3. **질문**: 하나의 질문만 한다. 답해야 할 항목 수가 여러 개면 개수를 명시한다(예: "2가지를 쓰시오").

## 7. 자료 작성 규칙

1. 자료는 공개된 취약점, 공식 문서, 표준 로그·설정 형식에 기반해 재구성한다.
2. 실행 가능한 공격 코드나 완성된 악성 페이로드는 넣지 않는다. 공격 예시는 취약점 식별에 필요한 최소 문자열 수준으로 제한한다.
3. 한 문항 안에서 시스템 환경(OS, 버전, 포맷)은 일관되게 유지한다.

## 8. 표기 규칙

1. 영어 약어와 용어는 번역하지 않고 원형을 쓴다(예: `XSS`, `IPS`, `PKI`).
2. 한 문항 안에서 약어가 처음 나올 때만 풀네임을 괄호로 병기하지 않는다.
3. 부연 설명용 괄호는 작성을 엄금한다.
4. 문항은 한국어로 작성하고, 명령어·코드·로그는 원형을 유지한다.

## 9. 법규 최신성 규칙

법규는 항상 최신 기준으로 출제한다. 국가법령정보센터(https://www.law.go.kr/lsSc.do, https://www.law.go.kr/sitemap.xml)를 근거로 하여 교차검증을 수행한다.

1. 법규·제도 문항(카테고리 h)은 기준표에 있는 사실만 출제한다.
2. 질문에 기준 시점을 명시한다(예: "2026년 10월 기준").
3. 시행 예정 사항은 시행일을 함께 밝히거나 출제하지 않는다.

## 10. 난이도 기준

`문제 유형.md`의 상/중/하 정의를 그대로 따르며, 이 자격증에서의 기준은 다음과 같다.

- **하**: 용어·정의·단순 비교(카테고리 a, g, h의 단답).
- **중**: 로그·설정·코드 해석, 원리 설명(카테고리 b, c, d, f).
- **상**: 복합 시나리오 분석과 대응 설계(카테고리 e, i, 실무형).
