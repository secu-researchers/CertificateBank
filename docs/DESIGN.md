# CertificateBank 설계안

## 목표
LLM이 SKILL 규칙에 따라 자격증 시험지를 생성하고, 웹에서 풀고 채점·피드백을 받아 로컬에 저장하는 개인용 Flask 앱.

## 확정된 결정
- 모델: 웹에서 선택 가능(생성·채점 각각). 기본값은 Claude Sonnet 5.5.
- 채점: 모든 유형을 LLM이 채점. 채점 규칙은 `문제 유형.md`에 기록.
- SKILL: 모두 Markdown. 문항 유형·서식·채점은 기존 퀴즈 규칙 체계(8종 유형, 문항 서식, 난이도, 풀이과정, 총평)를 차용해 프로젝트에 맞게 개량.
- 문제 오류 대응: 생성 단계에서 자가검증 2회 개선 루프(`생성 규칙.md`). 신고/정정 기능은 두지 않는다.
- 채점 전 예상 토큰 표시 없음.
- 토큰 절약: SKILL 본문을 프롬프트 캐시에 두어 생성·검증·채점 호출이 공유한다.

## 디렉터리 구조
```
CertificateBank/
├─ app.py
├─ certbank/
│  ├─ routes/        # generate, exam, grade, review
│  ├─ skills.py      # SKILL 로더
│  ├─ generator.py   # 배치 생성 + 자가검증 루프
│  ├─ grader.py      # LLM 채점
│  ├─ llm.py         # Claude 호출(모델 선택, 구조화 출력)
│  ├─ schema.py      # 문항·답안·채점 결과 검증, 통계 계산
│  ├─ storage.py     # JSON 읽기/쓰기
│  └─ qtypes/        # 유형 레지스트리(보기 규칙·답안 형식·부분정답 허용), 풀이 UI 조각
├─ skills/           # 문제 유형.md, 생성 규칙.md(핵심), 자격증별 .md
├─ data/
│  ├─ exams/{exam_id}.json       # 불변 원본: 빈 문항(user_answer=null) + 검증 기록
│  └─ attempts/{attempt_id}.json # 응시: 문항 사본 + 사용자 답안 + 채점 결과 + 총평
├─ templates/, static/
└─ docs/
```

## SKILL 로딩
- 요청마다 `skills/`를 디스크에서 다시 읽는다(캐시 없음).
- 생성 프롬프트 = `생성 규칙.md` + `문제 유형.md` + 선택한 자격증 SKILL.
- 채점 프롬프트 = `문제 유형.md`의 채점 규칙 + 선택한 자격증 SKILL + 문항·사용자 답안(정답은 입력에 없음).
- 자격증 목록은 `skills/` 스캔으로 구성(핵심 두 파일 제외). 자격증 SKILL 필수 항목은 `생성 규칙.md` 5절.
- 프롬프트 캐시: 위 SKILL 본문을 system 첫 블록으로 두고 캐시 중단점을 건다. 호출마다 달라지는 지침과 입력은 그 뒤에 둔다. 생성·검증 호출은 같은 본문을, 채점·총평 호출은 채점용 본문을 공유한다. 진행 화면의 `토큰 사용` 줄과 저장된 `usage`(캐시 읽기·쓰기)로 효과를 확인한다.

## 문항 유형 (8종)
TrueFalse, 사지선다형, 빈칸 채우기형(보기형/무보기형), 단답형, 서술형, 논술형, 단답형 실습, 서술형 실습. 서식은 `문제 유형.md` 3절. 유형 추가 = `문제 유형.md` 표 + `qtypes/__init__.py` 레지스트리 항목 추가.

## 생성
1. 요청 해석 → 배치 분할(최대 10문항) → 배치 생성 → 자가검증(최대 2회) → 조립.
2. 구조화 출력(tool use + JSON 스키마)으로 생성하고 Python에서 스키마를 한 번 더 검증한다.
3. 자가검증은 생성과 별도 호출. 필터 A(문항 완결성: 서식, 독립 풀이로 정답 도출성·모호성 확인, 사실·논리, 난이도), 필터 B(SKILL 범위·요청 분포·중복). 결함 문항만 재생성, 2회 후 실패 문항은 폐기하고 부족분은 사용자에게 보고.
4. 검증 기록을 시험지에 저장해 화면에서 확인.

## 채점
- 모든 문항을 LLM이 판정. 문항에 정답을 저장하지 않고, 채점 요청 시 LLM이 사용자 답안을 보고 정답을 판단해 평가한다.
- 문항별 결과: 정답/부분정답/오답, 점수, 채점자가 판단한 정답(`correct_answer`), 풀이과정(오답·부분정답 필수). rubric은 두지 않는다.
- 시험지 총평과 주제별 정답률 산출. 총점은 배점 지정 시에만.
- 시험지(`exams/`)는 수정하지 않고, 응시(`attempts/`)가 문항 사본에 답안을 채워 채점 결과와 함께 저장된다. 같은 시험지를 여러 번 풀 수 있다.
- 주제별 정답률과 총점은 LLM이 아니라 코드가 계산한다.

## API 키
웹 폼 입력, 디스크 저장 금지, Flask 세션(서버 메모리)에만 보관, 로그 기록 금지. 서버는 `127.0.0.1`에만 바인딩.

## 화면
시험 생성(자격증·모델·유형별 문항 수·난이도·범위·배점) → 풀이 → 채점 결과 → 오답 복습·주제별 통계 → 기록 목록. CSS 변수 기반 다크 테마, 프레임워크 없이 순수 CSS + 소량 JS.

## 구현 순서(Local Goals)
1. 뼈대 + SKILL 로더 + 다크 UI 기본 레이아웃
2. 스키마 + 저장소
3. LLM 호출 모듈(모델 선택, API 키 세션 보관)
4. 생성기(배치 + 자가검증 루프)
5. 풀이 화면
6. LLM 채점 + 피드백 저장
7. 복습·통계 화면
각 단계는 완료를 확인한 뒤 다음으로 넘어간다.

## 비용·위험
- 모든 문항을 LLM이 채점하고 생성마다 최대 2회 검증이 붙으므로 호출 수가 많다. 객관식 채점은 호출을 문항 묶음 단위로 합쳐 줄이고, 반복되는 SKILL 본문은 프롬프트 캐시로 줄인다. 캐시 최소 길이에 못 미치면 조용히 적용되지 않으므로 `토큰 사용` 줄의 캐시 읽기 값으로 확인한다.
- 정답이 저장되지 않으므로 채점자의 사실 오판이 점수에 반영될 수 있다. 채점 프롬프트에 자격증 SKILL을 포함하고, 풀이과정에 정답 근거를 쓰게 하며, 확신 없는 사실은 단정하지 않게 해 억제한다.

## 미결정 사항
1. 법령의 "실습"을 단답형 실습/서술형 실습으로 나눈 구조를 그대로 둘지, 하나의 "실습형"으로 합칠지.
2. 법령의 "설명 보고 용어 추리형"을 별도 유형으로 두지 않고 단답형에 포함시켰다. 분리가 필요한지.
3. 배치 크기(현재 10문항)와 검증 호출을 문항 묶음으로 처리하는 방식의 확정.
4. 자격증 SKILL(정보보안기사실기, AZ900) 초안 작성 시점.
